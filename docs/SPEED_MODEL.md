# AI 속도 예측 모델

마을버스 노선의 에너지와 탄소를 계산하려면 노선이 지나는 모든 도로의 시간대별 속도가 필요하다. 그러나 서울 표준노드링크 63,548개 중 29.25%(18,588개)는 속도 관측이 없고, 마을버스가 다니는 1차로 골목이 여기에 많이 포함된다. 이 문서는 관측이 없는 도로의 속도를 채우는 A/B/C 계층 모델의 데이터, 방법, 검증을 정리한다.

## 1. 분석 범위

| 항목 | 값 |
| --- | --- |
| 공간 | 서울 행정경계와 교차하는 방향성 표준 링크 63,548개 |
| 기간 | 2026-07-07~2026-07-20(14일). 레이더 원본이 없는 7월 7일 00시를 빼고 335개 시점 |
| 관측 링크 | 44,960개(70.75%) |
| 관측 팩트 | 15,094,335 링크-시간 행 |
| 전 링크 예측 | 335개 시점 × 63,548개 링크 |

분석 단위는 `LINK_ID`(방향 `F_NODE→T_NODE`)이며, 시간코드는 00시=1, …, 23시=24이다. 길이는 m, 속도는 km/h, 경사는 %, 강수는 mm이다.

## 3. 데이터 구축(`src/pipeline/`)

| 단계 | 하는 일 | 출력 |
| --- | --- | --- |
| 01 | 전국 표준노드링크 중 서울 경계와 교차하는 링크 추출(경계에 걸친 링크는 전체 형상 유지) | `data/interim/seoul_link.shp`, `seoul_link_attr.csv` |
| 02 | 5분 속도 CSV를 Polars lazy scan으로 읽어 서울 링크만 `LINK_ID×기준일×시간코드`로 평균. 실제 표본 수(`sample_count_5min`, 최대 12) 보존 | `data/interim/seoul_link_speed_5min_hourly.csv` |
| 03 | 기상청 HSR 레이더 60분 누적 강수 수집. `-25000`은 무강수(0mm), `-30000` 이하는 결측 | `data/raw/weather/radar/` |
| 04 | 링크 차원 표: 도로 속성, DEM 5지점 표고·방향성 경사, 도로망 위상, 시설, 교통·View-T, 생활인구 | `data/processed/seoul_link_dimension.csv` |
| 05 | 관측속도에 강수(링크 중심점 최근접 격자), 시간대 교통량, 생활인구 결합 | `data/processed/seoul_link_speed_fact.csv` |

**전처리 원칙**
- 표본 수: 한 시간 12개 5분 관측이 모두 있지 않은 경우가 있어 `sample_count_5min`을 학습 가중치로 쓴다.
- 결측: 교통량·View-T는 약 60.7%가 비어 있다. 미조사를 뜻하므로 0으로 채우지 않고 XGBoost가 결측 분기를 학습하게 한다. 시설 개수는 '없음'이 명확하므로 0으로 채운다.
- 경사: 90m급 DEM과 짧은 링크의 조합은 비현실적인 경사를 만들 수 있어 원값을 보존하고, 에너지·보행 계산에는 ±12%로 자른 값을 쓴다.

## 4. 계층형 속도 모델(`src/models/`)

A/B/C는 그 링크에 쓸 수 있는 **속도 정보의 수준**이다.

| 계층 | 링크 수 | 조건 | 방법 |
| --- | ---: | --- | --- |
| A | 44,960 | 자체 관측 이력 있음 | `LINK_ID×시간코드×평일/주말` 이력 평균(희소하면 링크×시간 → 링크 → 전체 평균으로 대체) |
| B | 16,752 | 자체 관측은 없으나 1·2칸 이웃 링크가 관측됨 | 이웃속도를 포함한 XGBoost(61개 변수) |
| C | 1,836 | 이웃 관측도 없음 | 이웃속도를 뺀 XGBoost(60개 변수) |

**이웃속도 정의.** 관측 이웃의 '같은 시간코드·평일/주말 과거 평균'을 쓴다(1칸 이웃 우선, 없으면 2칸). 같은 날짜·시간의 이웃 실측값은 미래 시점에 얻을 수 없으므로 쓰지 않는다. 학습과 예측이 같은 정의를 써서 학습·서빙 불일치를 막는다.

**C를 따로 둔 이유.** 하나의 모델에 이웃속도를 결측으로 넣으면 이웃이 없는 C 링크에서 성능이 크게 떨어졌다(C 단일모델 R² 0.25 대 분리모델 0.31). 그래서 이웃속도 열을 아예 뺀 모델을 따로 학습한다.

**변수(61개).** 도로 기본속성·지형·시간 22, 도로망 위상·파생 18, 같은 도로명 구간·도심거리 5, View-T 혼잡·평균속도 5, 시설·교통량 7, 생활인구 2, 이웃속도 1, 교차로 유형 1.

**설정.** `reg:squarederror`, 300 trees, learning rate 0.05, max depth 8, histogram tree, native categorical, seed 42, 표본 수 가중.

## 5. 알고리즘 선택(`notebooks/`)

| 단계 | 정보 | 평가 방식 | R² |
| --- | --- | --- | ---: |
| 전체 평균 | 없음 | 무작위 분할 | 0.000 |
| 제한속도 선형회귀 | 제한속도 | 무작위 분할 | 0.172 |
| 도로등급별 평균 | 도로등급 | 무작위 분할 | 0.266 |
| LightGBM / XGBoost / CatBoost | 도로 속성 23개 | 무작위 분할 | 0.610 / 0.632 / 0.556 |
| LightGBM / XGBoost | 정제 변수 약 60개(같은 시각 이웃 관측, 실험값) | 도로 단위 GroupKFold | 0.737 / 0.740 |
| **실제 적용 B(공식)** | 61개(이웃속도는 과거 같은 시간대 평균) | 도로 단위 GroupKFold | **0.723** |

- 무작위 분할은 같은 도로가 학습과 평가에 섞여 점수가 후하다. 그런데도 더 엄격한 도로 단위 분할에서 최종 모델이 더 높았다. 성능을 끌어올린 것은 알고리즘보다 데이터 결합으로 만든 변수였다.
- 0.740은 미래 시점에 얻을 수 없는 동시점 이웃 관측을 쓴 실험 상한이므로 공식 성능으로 쓰지 않는다.
- 하이퍼파라미터는 두 알고리즘 모두 기본값으로 통일했다.

**변수 중요도(SHAP).** gain은 상관된 변수 사이의 기여를 왜곡한다(초기 구성에서 통행제한차종의 gain이 71%였다가 구조 변수 추가 후 1.4%로 급락). 그래서 TreeSHAP을 기준으로 삼았다. B 계층 20,000행 기준 상위 변수는 이웃 도로 속도 35.6%, 시간대별 평균속도(View-T) 7.2%, 같은 도로명 구간 길이 4.6%, 시간대 3.3%, 진입차로수 평균 3.1%, 제한속도×차로수 3.0%다. 주변이 막히면 이 도로도 막힌다는 공간 상관이 예측의 핵심 근거다.

## 6. 검증

| 계층 | 검증 방식 | R² | MAE | RMSE | 오차 90% 이내 |
| --- | --- | ---: | ---: | ---: | ---: |
| A | 시간 순서 분할(과거 기간 학습 → 이후 3일 평가, `notebooks/03`) | 0.92 | 2.3km/h | 3.6km/h | — |
| B | 도로 단위 3-fold GroupKFold(이웃 조회표도 fold별 학습 도로로 재구성) | 0.72 | 4.6km/h | 6.4km/h | ±10.2km/h |
| C | 〃 | 0.31 | 5.7km/h | 7.5km/h | ±12.2km/h |

- B·C 값은 `python src/transit/checks/validate_bc_tiers.py`가 `02_build_model_bc.py --mode validate`를 그대로 돌려 계층별로 집계한 값이다(전체 R² 0.7226, 약 1시간 소요).
- C는 성능이 낮지만 마을버스 노선 길이의 2.5%에만 쓰인다.
- A는 요일별(7단계) 버킷이 셀당 표본 부족으로 과적합되어 평일/주말 2단계를 택했다.
- 마을버스 실측 속도(TOPIS 노선유형 통계, 2026.10)와 비교한 외부 점검은 `src/transit/09_validate_ai_speed.py`에 있다. 낮 시간 차이는 약 1km/h이고, 20~22시는 분석 속도가 약 2.5km/h 빠르다.
- AI 추정 구간 속도를 ±5km/h 바꿔도 마을버스 분석의 결론이 유지되는지는 `src/transit/checks/ai_speed_stress.py`로 확인한다.

## 7. 예측(`src/models/03`, `04`)

학습된 네 파일(`model_a_lookup.parquet`, `neighbor_speed_lookup.parquet`, `model_nb.pkl`, `model_stat.pkl`)을 재학습 없이 읽는다.

1. 시점(`tm`)을 날짜·요일·시간코드로 바꾼다.
2. 링크별 레이더 강수를 붙인다(`weather_snapshot.py`, 또는 `--precip-mm` 시나리오 값).
3. 실시간 값이 없는 교통량·인구는 같은 시간코드·평일/주말의 과거 평균을 쓴다.
4. A 조회값이 있으면 A, 없고 이웃이 있으면 B, 둘 다 없으면 C를 적용한다.
5. 예측속도를 3km/h와 링크 제한속도 사이로 제한한다.

`04_batch_predict_all_link_speed.py`는 기간 전체를 한 번에 예측해 시점별 `data/processed/all_link_speed_prediction_{tm}.csv`(각 63,548행, 결측 0)를 만든다. 마을버스 분석의 `src/transit/03`이 이 중 평일 시점을 평균해 링크×시간대 속도 프로필을 만든다.

## 8. 한계

1. 14일 자료라 계절성, 휴일·행사 효과를 대표하지 못한다.
2. A 조회표는 14일 전체로 만들었으므로 같은 기간에 대한 A 비교는 외부 시험이 아니다(공식 A 성능은 시간 순서 분할 값).
3. B·C 검증은 관측 링크를 가상으로 가린 대리 평가다. 실제 미관측 골목과 분포가 다를 수 있다.
4. 교통량·View-T는 2024년 평일 기준이고 약 60.7%가 결측이며, 실시간 값 대신 과거 프로필을 쓴다.
5. 강수는 링크 중심점 최근접 격자로 붙여 국지 강수의 공간 오차가 있다.
6. 경사는 DEM 해상도와 짧은 링크 때문에 오차가 있어 ±12%로 보정했다.
