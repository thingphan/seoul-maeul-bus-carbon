# 운행별 피크 예측과 차량 배치(`src/transit/upgrade/`)

평균 재차인원이 낮은 노선·시간대에도 특정 운행에는 승객이 몰릴 수 있다. 이 단계는 교통카드 기록으로 운행마다 최대 탑승 인원을 재구성하고, 앞으로의 운행 피크를 AI로 예측한 뒤, 소형 저상 전기차로 바꿀 수 있는 운행을 운영 제약 안에서 고른다. 결과는 [분석보고서](report/maeul_bus_integrated_report.md) 4)·5)절, 상세 수치는 [운행 검증 상세](report/maeul_bus_upgrade_validation.md)에 있다.

## 실행

```powershell
pip install -r requirements.txt
pip install xgboost==3.4.0                                      # 피크 모델 결과를 그대로 재현하는 버전
python -X utf8 -m src.transit.upgrade.run --download            # 카드 자료 수집부터 배치·민감도까지
python -X utf8 -m unittest discover -s tests -v
```

- 이미 받은 카드 자료를 쓰면 `--download`를 뺀다. 공개 ZIP(하루 약 0.5GB)에서 마을버스 태그만 남기므로 수집에 시간이 걸린다.
- 입력으로 기본 분석(01~07)의 `routes.csv`, `route_links.csv`, `route_priority.csv`, `route_hourly_load.csv`, `link_speed_weekday_profile.parquet`와 `seoul_link_dimension.csv`가 필요하다([마을버스 분석 단계](TRANSIT_MAEUL_BUS.md)).
- 이어서 탄소·접근성을 수정 에너지로 다시 계산하려면 `--integrated`를 붙인다([통합 재계산](MAEUL_INTEGRATED_REPORT.md)).
- `--report`는 이 단계만의 보조 보고서(PDF·마크다운)를 `output/`에 만든다. reportlab·PyMuPDF가 필요하다(`requirements-upgrade.txt`).

## 운행별 최대 탑승 재구성

- 승차·하차 태그를 시각순으로 누적한다. 같은 분의 승하차는 선후를 알 수 없어 순변화로 하한을, 승차를 먼저 두어 상한을 구한다. 하차 태그가 없는 승객은 상한에 더한다. 정원 판정에는 상한을 쓴다.
- 출발 전 승차가 있거나, 하차 미확인 승객이 5%를 넘거나, 관측 운행시간이 2~180분 밖이거나, 자정을 넘겨 끝난 운행은 검증 가능 표본에서 뺀다(전체의 75.7%가 검증 가능).
- 같은 차량·출발시각이 이웃한 날짜 파일에 나뉘어 있을 수 있어, 실제 출발일 기준으로 먼저 합친 뒤 운행을 만든다.
- 카드 번호는 읽지 않는다. 차량 식별자가 있는 개별 기록은 로컬에만 두고 커밋하지 않는다.

## 피크 예측 모형

- **변수:** 노선, 출발 시각·요일·주말·공휴일(2026.7.17 제헌절), 노선 길이·정류장 수, 노선 주변 고령 비율·대체수단 없는 승차 비중·의존도, 직전 7일 같은 노선·시간대의 피크 평균·95백분위·운행 수. 같은 날과 미래 날짜의 결과는 쓰지 않는다.
- **목표 정규화:** 노선마다 수요 규모가 달라 목표를 '직전 7일 피크 평균 + 2명'으로 나눠 학습하고 예측 후 다시 곱한다. 과거 기록이 없으면 학습 기간 평균을 쓴다.
- **분위수와 보정:** Q50·Q95·Q99를 학습하고 분위수가 교차하지 않도록 정렬한 뒤, 보정 주의 정규화 잔차 99번째 순서통계량만큼 Q99를 올린다(conformalized quantile regression 방식). 시간 의존성이 있어 99% 포함을 보장하는 방법은 아니다.
- **기간:** 학습 7/6~19, 보정 7/20~26, 개발 비교 7/27~8/2, 최종 검증 8/3~9. 정규화는 개발 주를 본 뒤 추가했기 때문에 개발 주는 최종 성능 보고에 쓰지 않는다. 최종 검증 주는 하루씩 앞날의 관측만 반영하며 순차 예측한다.
- **비교 모형:** 학습 기간 노선·요일·시간대 99백분위(과거 경험), 정규화 전 XGBoost, 직전 7일 변수를 뺀 XGBoost.

## 차량 배치(MILP)

- **차량 가정:** 소형차는 Karsan e-JEST의 휠체어 배치 정원(운전자 제외 16명)·105kWh 제원을 참조하고, 운행 질량 5t·냉방 3kW·Cd 0.5·전면적 5.75m²로 둔다. 국내 인증·보조금 대상 여부는 확인하지 않았다. 비교 기준은 노선별 실제 차종이 아니라 공통 7t 전기버스이므로, 감축량은 차량 크기 효과다.
- **에너지:** 기준 전기버스의 공기저항은 카운티 일렉트릭 마을버스 사양의 정속 338km로 보정한다. 정류장 정지·출발·체류는 정류장의 70%에서 정차, 20km/h 가속, 회생 50%, 15초 정차로 더하고, 충전 손실(효율 0.9)을 반영한다. 07~21시 밖은 가장 가까운 시간대 값을 쓴다.
- **결정 변수:** 노선별 설치 소형차 수(정수)와 차량·날짜별 하루 운행 묶음의 교체 여부(이진). 한 차량의 하루 운행을 통째로 바꾸므로 운행 중 교대나 차고지 간 차량 공유는 넣지 않았다.
- **제약:** 보정 Q99 예측 상한 ≤ 16명, 배터리 80% 사용 중 10% 예비를 남긴 하루 에너지(왕복 차고지 4km 포함), 노선별 설치 대수, 보정 7일 정류장 순서 일치, 카드 운행 수/공식 운행횟수 0.8~1.2, 단일 노선, 하루 태그 운행 3회 이상.
- **평가:** 보정 주로 노선별 차량 수를 정하고, 최종 검증 주에는 그 배분을 고정해 날짜별로 다시 적용한다. 노선별 이득이 날짜마다 분리되는 현재 구조에서는 한계편익 탐욕법도 같은 최적값을 내며, 코드에서 두 결과의 일치를 확인한다.
- **비용:** 차량 가격은 확인하지 못해 넣지 않았다. 전력비 200원/kWh 가정의 절감과, 그 절감만으로 상쇄되는 연간 차량당 추가비용을 계산한다. 이는 총소유비용(TCO)이 아니다.

## 한계

- 태그하지 않은 승객과 무승객 운행은 관측되지 않는다. 배치 운행의 15.7%는 정원 검증이 불가능했다.
- 여름 5주 자료만 썼다. 계절·학기 변화는 확인하지 않았다.
- 같은 정류장 순서가 과거 도로 경로까지 같다는 증거는 아니며, 에너지 거리는 API 경로와 날짜별 노선 거리 중 큰 값을 쓴다.
- 평일 도로 속도를 주말·야간에 근사 적용했다.
