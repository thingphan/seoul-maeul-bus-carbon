# 전체 프로젝트 통합 보고서와 재현

제출본은 [분석보고서 PDF](report/작다고감편하지마라_분석보고서.pdf)이며, 본문은 [통합 분석 보고서](report/maeul_bus_integrated_report.md)에 옮겨 두었다. 속도 AI·버스/승용차 탄소 비교·고령자 의존도/접근성·정책 잠재량·운행 피크 AI·차량 배치를 하나의 연구 흐름으로 연결한다. 이전 `maeul_bus_upgrade_report.md`는 운행 검증의 보조 기록이며 전체 연구 보고서를 대신하지 않는다.

## 실행

환경: Windows, Python 3.13. 공간 연산은 기존 `requirements.txt`의 GeoPandas/Shapely/Rasterio와 설치된 환경을 사용하며, 운행 AI 및 보고서는 `requirements-upgrade.txt`에 버전을 기록했다.

이미 모든 입력과 운행 검증 결과가 있으면 다음 세 명령으로 탄소·접근성을 다시 계산하고 통합 보고서를 생성한다.

```powershell
python -X utf8 -m src.transit.upgrade.integrated
python -X utf8 -m src.transit.upgrade.integrated_figures
python -X utf8 -m src.transit.upgrade.integrated_report
python -X utf8 -m unittest discover -s tests -v
```

교통카드부터 다시 실행하려면 `python -X utf8 -m src.transit.upgrade.run --download --integrated`를 사용한다. 기존 01~03 단계의 노선·속도·생활인구 및 보행 입력이 선행되어야 한다. 코드만 받으면 비공개 로컬 데이터 없이 즉시 전체 실행된다고 주장하지 않는다. 원자료 위치는 `data/README.md`, 기존 처리 절차는 `docs/TRANSIT_MAEUL_BUS.md`, 운행 검증 계약은 `docs/MAEUL_UPGRADE_IMPLEMENTATION.md`를 참고한다.

## 분석 단위와 비교 기준

| 분석 | 모집단·기간 | 질문 |
|---|---|---|
| 탄소·의존도·정책 유형·노선 제거 | 7월 집계 기반 247개 중 QA 17개 제외 230개. 운행횟수 7/6~31 | 노선이 승용차보다 효율적인가? 서비스 축소의 접근성 손실은 큰가? |
| 개별 운행 피크·AI·하루 고정 차량 배치 | 7/6~8/9 35일, 247개 노선. 개발과 분리한 최종 검증 8/3~9 | 평균 기반 후보를 실제 태그 피크와 운영 조건으로 확인하면 어디까지 남는가? |

두 모집단의 기간·분모가 다르다. 시간대 잠재 감축과 하루 차량 배치 감축을 같은 효과의 전후 값으로 오인하지 않는다. 전기화와 소형화 시나리오도 대상이 겹치므로 합산하지 않는다.

탄소 비교는 노선별 실제 차량을 관측한 배출이 아니라, 공통 7t 중형 전기 모형과 서울 연료 구성을 적용한 시나리오다. 경유/CNG는 서울 논문의 전기 소비 대비 비율을 이전한다. 승용차는 연료별 대표 차종을 적용한다. 공통 운행조건은 같은 도로 속도·방향성 경사이다. 도로 속도는 당일 버스 GPS가 아니다.

카운티 303/338km를 서로 다른 시험주기로 사용하지 않고 정속 Cd와 정지출발 소비를 분리했다. 버스와 전기 승용차 모두 충전효율 0.9의 전력 사용 경계를 적용했다. 정지출발·체류·냉방과 회생제동은 가정이며 실차 보정이 아니다. 실제 마을버스 대형 비중과 다른 공통 질량 가정의 영향은 배출 배율로 확인한다. 소형 제원의 국내 승인·노선 적합성은 미확인이다.

## 원본 보존·산출물

`data/processed/transit/`의 기존 입력은 보존한다. 복사한 입력과 재계산 결과는 `data/processed/transit_full/`에 저장하며, 실행 끝에 원본 SHA-256 불변을 검사한다. `transit_v2/`의 운행 예측·배치 결과도 별도로 유지한다.

- 제출본: `docs/report/작다고감편하지마라_분석보고서.pdf`(공모전 양식). 같은 본문을 `docs/report/maeul_bus_integrated_report.md`에 옮겨 두었다.
- 초안 PDF: `integrated_report` 실행 시 `output/pdf/서울_마을버스_탄소효율_이동권_통합분석보고서_5p.pdf`를 만든다. 제출본은 이 초안을 공모전 양식에 옮겨 방법·정책 서술을 다듬은 것이며 수치는 같다.
- 그림 PNG/SVG: `docs/report/images/integrated/`.
- 공개 가능한 재계산표: `docs/report/metrics/integrated/`.
- 탄소·접근성 요약: `transit_full/integrated_summary.json`.
- 피크 검증과 현재 정책 유형의 연결: `transit_full/integrated_findings.json`.

전체 보고서 수치는 새로 계산한 값이다. 과거의 218/230개, 98g, 15.54톤·7.53톤, 29개 소형화 후보를 새 모형 수치로 그대로 재사용하지 않았다. 경유/CNG 이전 비율·중형 가정·시점 차이 등은 여전히 한계다.

## 접근성 해석과 코드 수정

노선 하나를 제거하고 해당 노선만 정차하는 정류장을 제외해 가장 가까운 남은 정류장까지의 보행시간을 다시 계산한다. 목적지가 같은지, 환승·대기 부담이 얼마나 변하는지는 포함하지 않는다. 도로망과 직선×1.3 결과의 차이는 계산 방식의 범위이며 신뢰구간이 아니다.

원래 코드에서 기준 접근은 가능하지만 제거 후 연결이 사라진 격자를 영향 0으로 취급하던 부분을 고쳤다. 새 연결 상실을 영향 인구에 포함하고 별도 집계한다. 추가시간 평균은 유한한 영향 격자에 대해서만 계산한다. 새로 10분을 초과한다는 지표는 제거 후 **전체** 정류장 접근시간 기준이며 추가 보행 10분이 아니다. 고령 생활인구는 실제 고령 승객 수가 아니고 노선별 영향 인구를 합산하면 중복될 수 있다.

## 속도 AI와 운행 AI

도로 속도는 기존 A/B/C 모델 산출물과 저장된 검증 기록을 재사용한다. 전체 도로 관측 이력이 없는 구간을 모형으로 보완하며, 관측 이력 조회인 A와 당일 실측을 구분한다. 이번 통합 보고서 작성에서 B/C를 다시 학습했다고 주장하지 않는다.

피크 모델은 7/6~19 학습, 7/20~26 오차 보정, 7/27~8/2 개발 비교, 8/3~9 최종 검증이다. 과거 자료로 만든 피처만 사용하며 자정을 넘겨 종료되어 다음 날짜 시작 시 확보되지 않은 운행은 검증 가능 표본에서 제외한다. 배치 후보의 15.7%는 태그 품질상 검증 불가능하며, 이것을 정원 충족으로 간주하지 않는다. 국내 차종·실제 차고지·무승객 운행 확인 전까지 배치는 시범 검토 시나리오이다.
